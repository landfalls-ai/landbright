# History

Every change in order, newest first, with the decisions taken along the way. One row per commit.

| Date | Commit | Change |
|---|---|---|
| 2026-11-12 | Wave 1, conformance and Landflow | **Wave 1: the OpenID conformance suite** ([spec 002](../specs/002-identity-core/plan.md#conformance-suite-t012b), T012b). `pnpm conformance` runs the OpenID Foundation's suite (release v5.3.4, pinned) in Docker (`deploy/conformance/compose.yml`, project `landbright-conformance`) against a dedicated identity plane behind Caddy's TLS: OIDC basic plan, 35 modules, 21 passed, 5 warnings, 4 skipped, 4 for review, 1 failed. New `LANDBRIGHT_TRUST_PROXY` and `LANDBRIGHT_PKCE_OPTIONAL_CLIENTS` (empty by default; only the run sets them). Decisions: PKCE stays required except for client ids named for the run; TLS from a proxy, not in the services; POST to the authorization endpoint stays off (oidc-provider allows it only with a `SameSite=None` session cookie). Bug it found, fixed: an app asking for `prompt=consent` (needed for `offline_access`) looped on `/interaction`; the interaction now answers the consent prompt, and the e2e tests cover a refresh token. **Wave 1: the real Landflow signs in** (T013). Landflow's own image as a throwaway instance with host networking (`deploy/landflow/compose.yml`, project `landbright-landflow`), so the Landflow in use and its repository are untouched; registered in the development Landbright; the administrator arrives as a Landflow admin and Tal as a member through the group map; a deactivated person is refused ([suite.md](suite.md#try-it-landflow-signs-in-through-landbright), screens 30 to 34). |
| 2026-11-12 | Wave 1, passkeys and key rotation | **Wave 1: passkeys** ([spec 002](../specs/002-identity-core/plan.md#passkeys-t010b), T010b). Sign in with a passkey alone, use one as the second step, add one when offered a second step; `@simplewebauthn/server`; one content-hashed script under `script-src 'self'`; the person page counts passkeys and the reset removes them; Settings lists them; a software authenticator in the e2e. Decisions: the issuer is `http://localhost:4402` (WebAuthn refuses IP addresses; the listener stays on 127.0.0.1); user verification required, so a passkey alone is two factors; `amr` adds `mfa` for two factors (TOTP sign-ins now say `["pwd", "otp", "mfa"]`); discoverable credentials; passkeys added only at sign-in until there is an account page. **Wave 1: the console and sign-in pages in real Chromium** (T012a). Playwright 1.62 in `e2e/browser/`: the administrator signs in and builds the directory through the console, people set passwords from the invite email, add a passkey (Chrome's virtual authenticator, so the pages' own script runs) or an authenticator app, and sign in to a Landflow-shaped app; `pnpm test:browser`, `pnpm screenshots` writes all 27 screens to `docs/screenshots/` ([screens.md](screens.md)). `startStack({ console: true })` runs the built console. Diagrams of the suite and of Landbright's processes ([suite.md](suite.md)). **Wave 1: signing-key rotation** (T011b). Settings → *Rotate* (`POST /api/settings/signing-keys/rotate`, audited): a new key signs, the replaced key stays published, older keys are retired. The key code moves to `libs/persistence` (`signing-keys.ts`) so control can rotate; the identity plane rebuilds its provider when the published set changes (`OidcProviderRef`, checked at most every five seconds). New `LANDBRIGHT_ID_TOKEN_TTL_SECONDS`. Decisions: two published keys at most; a rotation waits until the replaced key's ID tokens have expired instead of retiring it early; no message bus, an on-demand check. The browser story's screenshot of the client secret now masks the secret. |
| 2026-11-12 | Wave 1, second step | **Wave 1: a second step at sign-in** ([spec 002](../specs/002-identity-core/tasks.md), T010a, T011a). TOTP after the password (setup with a QR code, *Not now* for 30 days, single use per step, sealed keys), `amr` in the ID token, Settings (*Require a second step*, signing keys), the administrator reset; migration `second_factor` (tenant `mfa_required`; credential `counter`, `external_id`, `transports`, `label` for passkeys next). Decisions: a code once per 30-second step; a wrong code counts toward the password lockout; *Not now* fails toward asking again. Bugs fixed in the live check: the sign-in stylesheet was cached across a change (now content-hashed and immutable); `amr` was missing from the ID token (our claims map hid it); the setup key wrapped under its label; the services hung on restart while a browser held a keep-alive connection (`forceCloseConnections`). The brand mark above the sign-in card is gone. |
| 2026-11-12 | Wave 1, first slice | **Wave 1, first slice: identity core and sign-in** ([spec 002](../specs/002-identity-core/spec.md)). `libs/persistence` (Prisma, forced row-level security, hash-chained audit, bootstrap), the OIDC provider and sign-in pages, console sign-in and the directory, applications and audit APIs and pages, invite mail, `e2e/`. Decisions: signing keys sealed in Postgres instead of OpenBao (dev-mode OpenBao forgets them); client secrets derived, never stored; group names are the `roles` claim; no consent screen for administrator-registered apps; console as a backend-for-frontend with an Origin check on writes; lockout fails open; `/api/health` for administrators. Bug fixed in the live check: "1 groups". |
| 2026-11-12 | first commit | **Wave 0: foundations** ([spec 001](../specs/001-foundations/spec.md)). Workspace, idp and control services, console, `@land/tokens`, contracts, platform, compose infrastructure, tracing, the verify gate, the constitution v1.0.0, these docs. Decisions: services are CommonJS (Landfall's setting; Node 22.12 can `require()` ESM-only `oidc-provider`); infrastructure on 57xxx ports, away from Landflow's; `/api/health` public until wave 1; Valkey without an offline queue so a down Valkey reports at once. |
